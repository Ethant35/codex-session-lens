# Weekly usage
Author: Ethan

Open **Weekly usage** in the HUD. Choose the first and last calendar dates, then choose **Scan date range**. Both dates are included in the Mac’s time zone. The default is the previous Monday through Sunday. Add both `~/.codex/sessions` and `~/.codex/archived_sessions` in Settings to include active and archived local history. The scan reads only configured folders, runs on request, and can be cancelled. With the HUD watcher paused, **Scan once while HUD is paused** performs only the requested history scan and keeps the watcher paused. Synthetic sample mode must be off.

The report ranks projects by input plus output. Cached input is a subset of input, so it is not added again. Expand a project to inspect the contributing session IDs. Each session shows its own usage, parent ID and descendant usage. Descendant totals are informational: the project and grand totals already include each descendant under its own session. A short project ID distinguishes repeated folder names. Project labels come from source metadata for this requested report even when optional HUD project labels are off. Full project paths and message text are not returned.

The history scanner reads plain JSONL, Zstandard JSONL (`.jsonl.zst`) and gzip JSONL (`.jsonl.gz`). The Mac app uses its native Zstandard decoder. CLI runtimes without that decoder use the local `/opt/homebrew/bin/zstd` program; `LENS_ZSTD_BINARY` may select another executable. A missing decoder or broken archive appears under Coverage gaps. The existing continuously watched HUD cache still supports plain JSONL only; a weekly scan does not add compressed history to that cache.

Date totals use observed usage timestamps and cumulative changes with earlier baseline records. A delta that spans the range boundary can have uncertain timing. Missing baselines, counter resets, malformed records, missing parents and attribution conflicts appear in the report or session details. Read these before treating a total as complete. Scan coverage counts and general decoder/oversized-record warnings describe the entire scanned history. Session gap notes can also come from records outside the selected dates. They do not state that the same number of billable requests is missing from the chosen week. Files can be missing from the folders without a detectable error; no report proves complete billing history. Source files are untrusted and remain read-only.

Reports are held in memory. A new scan replaces the report; cancelling discards partial results. Clear telemetry, recovery, folder changes, sample mode, setup and pause changes clear the report and stop active scans. Closing the window stops the scan. A large scan runs in a separate worker so HUD controls and cancellation remain available. Reports do not create model requests.
