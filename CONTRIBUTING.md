# Contributing
Author: Ethan

Use macOS on Apple Silicon, Node.js 22.13.1 or later, and npm. Clone this repository into its own directory. Run `npm ci`, `npm run prepare:electron`, `npm run build`, `npm run package:mac`, then `npm run test:e2e`. `npm run dev` builds and launches the local application. It does not use a remote development server or hot reload.

Run `npm test` for routine checks. This builds the CLI and runs real JSONL/SQLite integration checks in plain Node.js. It never starts Electron, opens a window, changes focus, or calls a model. Use core tests for parser and storage behavior. Use the separate hidden `npm run test:e2e` suite only when a UI or Electron integration change needs it. The package must exist before E2E tests run. `LENS_EXECUTABLE` can point to an installed copy of the app executable. `npm run test:e2e:real` requires a signed-in local Codex CLI and a running installed Codex desktop; it performs one small real model turn using the normal Codex account. It does not use an API key or alter Codex config. Do not use private conversation fixtures.

Keep accounting conservative. Unknown is preferable to a fabricated exact number. Changes to parsers must explain observed source fields, replay behavior and accounting provenance. Keep source files read-only. Do not log raw malformed records, prompts, paths containing private data, credentials, or response text.

GitHub Actions are intentionally disabled for this repository at the maintainer's request. Do not add or dispatch workflows. Run acceptance locally and record reproducible sanitized evidence. Use feature branches and pull requests; never force-push. Preserve the MIT license. Author artifacts as Ethan where identity metadata is supported, without altering factual tool provenance.

For the v1 upgrade gate, retain a v1.0.0 packaged executable and run `LENS_ALLOW_VISIBLE_BASELINE=1 LENS_BASELINE_EXECUTABLE="/absolute/path/to/v1/Codex Session Lens" npx playwright test tests/migration.spec.ts`. The baseline app itself creates the old database; the current package must recover suppressed records and preserve removed-source history and preferences. This extra gate is separate from the deterministic suite so ordinary contributors do not need an old release to run that suite. For current hidden upgrade checks use `LENS_BASELINE_EXECUTABLE="/absolute/path/to/v1.0.1/Codex Session Lens" npm run test:upgrade`, with LENS_EXECUTABLE selecting the candidate. Do not launch v1.0.0 visibly without an explicit user request; preserve its historical migration evidence and state the limit.

Tests and preview captures use `--background` by default. The harness verifies that the window is hidden, unfocused and not focusable, and that the macOS Dock icon is hidden. Do not run visible tests on the user's desktop without an explicit request. `LENS_VISIBLE_TESTS=1` is an opt-in for deliberate visual debugging. The old v1 binary has no background mode, so its separate migration gate refuses to launch unless `LENS_ALLOW_VISIBLE_BASELINE=1` is explicitly supplied. Existing recorded migration evidence remains valid when only the test presentation mode changes.
